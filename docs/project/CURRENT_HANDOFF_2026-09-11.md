## GitHub 이전 업데이트

메모 작성 후 사용자가 최종 파일의 GitHub 업로드를 승인했다. 이 문서를 포함한 커밋은 서비스 소스·최종 이미지·재현 스크립트·검토 기록을 함께 묶은 이전용 스냅샷이다. 아래의 “미커밋/미푸시” 설명은 메모 최초 작성 시점 기록이다. 이 커밋이 origin/main에 반영된 후에는 새 컴퓨터에서 clone 또는 pull하여 이어갈 수 있다. 설치 폴더·빌드 출력·도구 트레이의 중복 확인 파일은 제외한다. 브라우저 작품은 여전히 별도로 이전해야 한다.

## 2. 사용자 요구사항과 확정 방향

- 별도 서비스로 웹을 먼저 개발하고 이후 앱을 개발한다.
- 한국이 주 시장이며 한국어와 영어를 제공한다.
- 주요 사용자는 여성 중심의 20대 성인 및 중고등학생. 트렌디하고 힐링 느낌의 디자인.
- 출시 목표는 3개 테마 × 테마당 2개 세트 = 6세트. 3단계 난이도는 폐지하고 모든 세트를 단일 고급 수준으로 구성한다.
- 세트당 개별 배치 가능한 스티커 최소 75개 이상. 기존 25/50/100개 상한은 폐기하며 새 상한은 성능 검증 후 결정한다.
- 사용한 스티커는 오른쪽 목록에서 제외하고 삭제 시 복귀한다. 저장 복원·실행 취소/다시 실행에도 동기화한다. 복제 기능과 난이도 선택은 제거했다. 실제 75개 이상 콘텐츠 제작은 아직 남아 있다.
- 특정 스티커의 애니메이션과 효과음, 화면에 맞는 배경음 선택, 추후 음악 추가, 무음 기능 필요.
- 원페이지가 아니라 메인·테마·이용방법·특징·About·법적 안내 등을 독립 페이지로 제공한다. 이용방법은 이미지로 자세히 설명하고 특징/About도 SEO를 고려한다.
- 1차는 광고 수익 모델, 개인정보 최소화, 진행 사항은 사용자 기기에 저장한다.
- 2차는 콘텐츠 결제. 필요한 정보만 추가 수집할 수 있도록 설계하되 계정/결제는 아직 구현하지 않는다.
- 새로운 디자인은 구현 전에 사용자 확인을 받는다. 승인된 자산의 조립·보정과 새 디자인 제안을 구분한다.
- 사용자는 Sol로 충분한 단계와 Astra가 도움이 되는 단계를 미리 안내받기를 원한다. 모델이 자동 전환됐다고 말하지 않는다.
- 현재 온실 시제품은 흰 종이 테두리 없는 오브젝트 방향으로 변경했다.

## 3. 지금까지 완료된 작업

### 서비스 화면과 정보 구조
- React + TypeScript + Vite 기반 기존 앱 유지.
- 한국어/영어 홈, 테마, 이용방법, 특징, About, 개인정보, 약관을 독립 경로로 구성.
- 광고 설정 및 작업실은 별도 유틸리티 화면.
- 3개 테마·6개 세트 탐색 구조. 실제 기존 자산으로 제작 가능한 것은 온실과 카페이며 나머지는 준비 중.
- 정적 HTML 사전 생성, 페이지별 제목·본문, 실제 링크, 배포 도메인에 따른 canonical/hreflang/sitemap 처리.
- 미리보기는 noindex. 작업실·광고 설정·404도 noindex.

### 편집, 저장, 음악
- 이동·크기·회전·반전·레이어·잠금·복제·삭제, 실행 취소/다시 실행, 감상 모드 등 기존 기능 유지.
- 회전 버튼이 가려지는 문제를 수정해 선택 도구를 작품 영역 밖에서 조작하도록 변경.
- PNG에 배경만 저장되던 문제 수정. 현재 세트의 스티커까지 합성하고 로딩 실패는 오류 처리.
- PNG는 정지 이미지이므로 음악, 애니메이션, 편집 데이터는 포함하지 않는다.
- Web Audio 기반 분위기 3종, 배경음 없음, 전체 음소거, 음량 선택.
- 최초 무음이며 사용자가 명시적으로 재생해야 시작한다. 설정은 사용자 기기에 저장.
- 실제 음원 파일 선택/추가용 콘텐츠 운영 체계나 영상 저장이 완성된 것은 아니다.

- 운영 SITE_URL 설정 시 법적 운영 정보가 비어 있으면 빌드 실패하도록 보호.

## 5. 새 컴퓨터 실행 및 검증

1. 현재 변경사항을 포함한 저장소 전체를 준비한다.
2. Node.js와 npm을 설치한다. 최근 실행 환경은 Node 24.18.0이며 다른 버전은 다시 검증한다.
3. 저장소 루트에서:
   npm ci
   npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
4. 별도 터미널에서:
   npm run verify
5. 위 통합 시제품 주소를 연다. 5174가 사용 중이면 포트를 선택하고 URL도 맞춘다.
6. 자산이 누락되지 않았는지 확인하고 편집·재접속·PNG·소리·모바일을 확인한다.

npm run verify는 TypeScript/Vite 빌드, 정적 페이지 사전 생성, 레이어/히스토리 검사, 정적 HTML 검사를 포함하며 마지막 테두리 연결 후 통과했다.
scripts/test-browser.cjs와 scripts/test-workbench.cjs는 별도 Playwright 및 Chrome이 필요하다. Playwright는 package.json에 직접 등록되어 있지 않고 기존 PC의 번들 환경을 이용했다. 새 환경에서는 별도 준비가 필요하며 기존 PC의 NODE_PATH 절대경로를 복사하지 않는다.
test-browser.cjs는 TEST_BASE_URL을 지원하고 test-workbench.cjs는 5174 주소를 사용한다.
작업대 브라우저 조작 검사는 이전 단계에서 통과했으나, 통합/최종 테두리 변경 후 전체 브라우저 조작·모바일·PNG 회귀 검사를 다시 수행한 것은 아니다.

## 6. 사용자 작품의 이전 — 소스와 별개

- 작품과 소리 설정은 localStorage에 있으며 Git이나 프로젝트 폴더 복사로 이동하지 않는다.
- 브라우저 프로필, 프로토콜, 호스트, 포트가 다르면 저장 공간도 다르다. localhost와 127.0.0.1도 다르다.
- PNG 저장만으로는 편집 가능한 작품을 복구할 수 없다.
- 편집 가능한 작품의 공식 파일 내보내기/가져오기 기능은 아직 없다. 작품을 옮겨야 한다면 기존 브라우저에서 별도 백업 절차를 먼저 마련한다. 사용자 승인 없이 저장 데이터를 초기화하지 않는다.
- 저장 키 예시:
  qk-diorama-saved-glasshouse-botanist
  qk-diorama-saved-glasshouse-shelf-intermediate-pilot-v1
  qk-diorama-saved-glasshouse-workbench-intermediate-pilot-v1
  qk-diorama-saved-glasshouse-combined-intermediate-pilot-v1
